# فاميلي كير — إدارة العيادة

تطبيق عربي RTL لإدارة العملاء والزيارات والكشف والخدمات والتحصيل والتأمين والأطباء والمتابعات والعروض والرسائل. الواجهة React/Vite، والبيانات في مشروع Supabase الذي أنشأه المالك `family care` داخل مؤسسة `peter`. كل رسائل النظام حالياً بمزود تجريبي يسجل النتيجة في قاعدة البيانات ولا يرسل SMS أو واتساب.

لشرح العمل اليومي حسب الصلاحيات، افتح [دليل الاستخدام PDF](docs/family-care-user-guide-ar.pdf) أو [النسخة النصية](docs/USER_GUIDE.md). لإعادة تصوير شاشات الدليل: `npm run guide:screens` (يشغّل البرنامج محليًا ببيانات عيادة وهمية من scripts/guide-fixtures.mjs، ولا يتصل بقاعدة البيانات). لإعادة توليد الـ PDF: `npm run guide:pdf` (يحتاج Python مع pypdf وpypdfium2 وPillow).

للاستقبال تسجيل سريع من «العملاء ← تسجيل عميل وخدمة»؛ يطلب الاسم والموبايل والنوع والطبيب والخدمة والتاريخ، ويُظهر النقابة أو شركة التأمين عند الحاجة. يكتب الاستقبال نسبة تحمّل العميل من الكارنيه لكل زيارة، ويمكنه تسجيل المبلغ المدفوع فوراً؛ تظهر معاينة حصة العميل والجهة والمتبقي. تُحفظ الزيارة والخدمة والإيصال معاً، وتُثبت مديونية الجهة للتسوية. زر «عميل فقط» يبقي المسار المفصل، و«حجز فقط» متاح لعميل مسجل. المالك يدير بيانات الجهات والتواصل من «التأمين والنقابات» دون نسبة افتراضية. الدليل النصي يشرح المسار الجديد؛ نسخة PDF المصورة توثق المسار التقليدي.

## تشغيل نسخة جديدة

يتطلب Node.js 20.19+، واتصال إنترنت، وصلاحية على مشروع Supabase `xkbyxefvzlcnyefkxwsx`. لا تشغّل السكربتات على مشروع Supabase آخر؛ كل سكربت يتحقق من مرجع المشروع والمؤسسة قبل الكتابة.

```powershell
npm ci
Copy-Item .env.example .env
```

املأ في `.env` مفتاح `SUPABASE_ACCESS_TOKEN` لمشروع `peter`، و`SUPABASE_DB_PASSWORD` بين علامتي اقتباس (مهم لو فيه `#`)، ويمكنك تحديد `OWNER_EMAIL` اختياريًا. بدلاً من المفتاح يمكنك تسجيل دخول Supabase CLI محلياً. لا تضف أي سر إلى متغير يبدأ بـ `VITE_`؛ سكربت الاتصال يكتب مفتاح النشر العام فقط للمتصفح.

```powershell
npm run connect
npm run migrate
npm run seed
npm run deploy
npm run verify
npm run dev
```

افتح العنوان الذي يطبعه Vite (عادة `http://localhost:5173`، وقد يختار منفذًا آخر لو مشغولاً). `connect` يتحقق من المؤسسة والمشروع، ويملأ عنوان API والمفاتيح في `.env` دون طباعتها. `migrate` يطبق ملفات SQL تصاعدياً فقط ويتحقق من بصمتها عند الإعادة. `seed` قابل للإعادة؛ ينشئ قائمة الخدمات والأسعار ومالك النظام إن لم يوجد. بريد المالك وكلمة مروره يُحفظان في `.env` المحلي؛ لا تُطبع كلمة المرور. `deploy` ينشر وظيفتي إدارة المستخدمين واستقبال تقييم الزيارة. رابط التقييم صالح 30 يوماً ولمرة واحدة، ولا يعرض اسم العميل أو بياناته. يُنشأ بعد إنهاء الزيارة للعملاء الموافقين على رسائل المتابعة. الردود تظهر للمالك فقط، والرسائل تظل تجريبية ولا ترسل SMS أو واتساب.

## التحقق

```powershell
npm run lint
npm run typecheck
npm test                       # اختبارات وحدات فقط، لا تتصل بقاعدة البيانات
npm run build
npx playwright test -c playwright.smoke.config.mjs   # البناء النهائي بهيدرز الأمان
```

اختبارات قاعدة البيانات والواجهة لا تعمل إلا بعد تسمية المشروع صراحة؛ مشروع العيادة الحقيقي يحتاج موافقة التنظيف المتتبَّع:

```powershell
$env:FAMILY_CARE_TEST_TARGET='xkbyxefvzlcnyefkxwsx'
$env:FAMILY_CARE_ALLOW_PRODUCTION_FIXTURES='tracked-cleanup'
npm run test:db        # معاملات تُلغى بالكامل + اختبار API بتنظيف متحقَّق منه
npx playwright install chromium
npm run test:e2e
npm run measure:loading
```

كل سجل تجريبي يُسجَّل في `output/playwright/fixture-ledger/` ويُنظَّف بالمعرّف عند نهاية الاختبار؛ أي فشل في التنظيف يُفشل الاختبار. لو توقف تشغيل في المنتصف: `npm run fixtures:cleanup -- <ledger.json>`. التفاصيل في `docs/QA-REMEDIATION.md`. للاحتفاظ بسجلات المال والتدقيق مع إخفاء ملفات العملاء التجريبية وإيقاف رسائلهم:

```powershell
npm run archive:demo
# لمجموعة معينة فقط:
npm run archive:demo -- --batch=<demo-batch-uuid>
```

الأرشفة لا تحذف المدفوعات أو الفواتير أو سجل التدقيق، ويمكن إعادة تشغيل الأمر بأمان. سجلات الطبيب وشركة التأمين والعرض المعلّمة بأنها تابعة للمجموعة التجريبية تُعطّل أيضاً، وتختفي من شاشات التشغيل؛ تاريخها المالي محفوظ للمراجعة في قاعدة البيانات.

## نشر الواجهة على Cloudflare Pages

المستودع الخاص هو `minadiaaaaaa/family-care`، ومشروع Pages هو `family-care` على `https://family-care-4le.pages.dev`. يدفع ملف `.github/workflows/cloudflare-pages.yml` كل تحديث لفرع `main` تلقائياً إلى المشروع نفسه عبر GitHub Actions. البناء يحتاج متغير المستودع `VITE_SUPABASE_ANON_KEY` (مفتاح Supabase القابل للنشر) والسر `CLOUDFLARE_API_TOKEN` (رمز Cloudflare بصلاحية Pages Write). عنوان Supabase مثبت في سير العمل على مشروع `family care` داخل `peter`. لا تضف مفتاح `service_role` أو كلمة مرور قاعدة البيانات إلى GitHub أو إلى متغيرات `VITE_`.

هذا مشروع Pages بدأ بالرفع المباشر، لذلك يستخدم GitHub Actions للنشر المستمر دون استبدال رابط الموقع. يمكن تشغيل سير العمل يدوياً من تبويب Actions. رمز النشر ينتهي في 10/10/2027 ويجب تجديده قبل ذلك للحفاظ على النشر التلقائي. لا ينشر سير العمل ترحيلات قاعدة البيانات أو وظائف Supabase؛ استخدم أوامر النشر المحلية المذكورة بالأعلى لهذه الأجزاء.

## قرارات تحتاج مراجعة قبل الاستخدام الفعلي

قائمة فاميلي كير فيها 43 بنداً كما وصلت، ومنها ساعة البنج الأولى **3500 جنيه** والثانية **300 جنيه**، ونايت جارد **1999** ونايت جارد الفك **1800** كبندين مختلفين. توجد مراجعة مفصلة في [ASSUMPTIONS.md](docs/ASSUMPTIONS.md) وملف الأسعار [family-care-catalog.json](supabase/seed/family-care-catalog.json). قائمتا «عيادات مصر» و«الأقارب» نسخ مبدئية معلّمة للمراجعة؛ قائمة النقابة وقائمة التأمين القديمتان محفوظتان للتاريخ، والزيارات الجديدة للنقابة والتأمين تستخدم سعر فاميلي كير. اختر مزود SMS أو واتساب واعتماد القوالب قبل تشغيل إرسال حقيقي.

الأسعار تُحفظ بقروش صحيحة ونسخة السعر وقت الزيارة لا تتغير مع تحديث القائمة. التصحيحات المالية عكسٌ مسجل بدل الحذف. الدخول عبر Supabase Auth، وصلاحيات قاعدة البيانات تفصل المالك والاستقبال والطبيب. راجع [DATABASE.md](docs/DATABASE.md) و[PLAN.md](docs/PLAN.md) لمعرفة التصميم وحالة التحقق.
